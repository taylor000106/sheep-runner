## B 类｜规格硬约束（换素材时必须满足，否则测试红）

`verify_assets.js` 有 8 条断言逐项卡这些值。改图不满足就 `verify_assets` 挂。

| 约束 | 具体值 | 断言 |
|---|---|---|
| 四档尺寸全都要有 | 640 / 512 / 256 / 128 | P6 |
| 640 母版 | 帧间 gap = 24px，图高 = 4×640 + 3×24 | P6 |
| 512/256/128 | gap = 0，图高 = 4×S | P6 |
| 锚点 x | `S/2 - 0.5`（640 档为 320，属实测容差） | P6 |
| 锚点 y（脚底） | **四帧必须完全相同**：640=603 / 512=483 / 256=241 / 128=120 | P6 |
| 单帧文件 | `sheep_run_1..4.png` 三档各 4 张，均 S×S 正方形 | P7 |
| GIF 预览 | `run_8fps / 10fps / 12fps` 三份，文件头合法 | P8 |
| 播放器 | `assets/preview/frames_player.html` 能跑、四帧都在轮播 | P1/P2 |

补充约束（不在断言里但代码写死、改了会出视觉 bug）：
- `RUN_ANCHOR_Y = 241`、`RUN_REF_CONTENT = 223.5` 写死在 `js/game.js`，**换图后必须同步改这两个常量**，否则角色会整体变大变小
- `HIT_DIP_MAX_DX = 81.5` / `HIT_DIP_MAX_UP = 195` 是按受击图实测轮廓写死的，受击图改了要重测

## F 建议的推进顺序

1. **先定画风**：确认 `xiaoyang-front-v2.png` 的画风分寸对不对。这道关不过，后面画多少都是废稿。
2. **画背面**（C3）：这是**唯一真正影响游戏画面的视图**，优先级应高于侧面和表情。
3. **做 4 帧跑步 + 1 张受击**（A1/A2）：按新版画风重出，然后过 `verify_assets` + 重新测锚点。
4. 侧面 / 四分之三 / 表情（C4–C6）：纯设定表用途，可以最后做，或干脆不做。
