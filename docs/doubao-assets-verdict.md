## 二、不合格项（关键）

### 2.1 跑步四帧：不是有效跑步循环

量测条件：按头宽归一化（基准头宽 841px）+ 头中心对齐中轴 + 脚底对齐同一基线。
即：**已经用程序消除了构图偏移，剩下的仍不对。**

**① 着地点相对中轴，四帧单调左移，不是左右交替**

| 帧 | 着地点偏移 | 应有的样子 |
|---|---|---|
| F1 | +21.7 px | 偏右（右腿支撑） |
| F2 | −47.4 px | 居中（腾空） |
| F3 | −215.6 px | 应偏左约 −20（左腿支撑） |
| F4 | −248.7 px | 应居中约 0（腾空） |

F3/F4 偏了 215–249px，相当于头宽的 26–30%。正常跑步循环着地点应在中轴两侧小幅摆动，不可能单方向越走越远。

**② 没有任何一对构成镜像**

| 对比 | IoU |
|---|---|
| F1 vs 镜像(F2) | 0.778 |
| F2 vs 镜像(F3) | 0.733 |
| F3 vs 镜像(F4) | 0.671 |
| F4 vs 镜像(F1) | 0.734 |
| *旧素材 F1 vs 镜像(F3)* | *0.950（基线）* |

旧素材能做到 0.950，新图全部 0.67–0.78。四帧是四个各自的独立姿态，不构成对称循环。

**③ 每帧蹄子数量和大小都对不上**

| 帧 | 主要深棕蹄子块 | 面积 |
|---|---|---|
| F1 | 2 个 | 3150 / 6374（差 2 倍） |
| F2 | 3 个 | 1006 / 10598 / 11238 |
| F3 | 2 个 | 15007 / 16823 |
| F4 | 2 个 | 6592 / 7609 |

F1 最大蹄块 6374，F3 最大 16823，**差 2.6 倍**。同一只羊的脚不可能一帧大一帧小到这种程度——说明每帧的腿是各自重画的，没有锁定一致性。

**④ 头身比不一致**：头宽/内容高 = 0.675 / 0.677 / 0.702 / 0.653，最大差 7.5%。

**直接后果**：四帧做成 GIF 会看到角色左右横移 + 腿忽大忽小，不像跑步，像原地打滑。已生成 `run4_current_4fps.gif` 实测确认。

### 2.2 受击图：根本没有蹲下

头宽归一化后对比：

| | 高/头宽 | 宽/头宽 |
|---|---|---|
| 站立（09_back_idle） | 1.474 | 1.001 |
| 受击（05_hit_crouch） | **1.438** | **1.003** |
| 提示词要求 | 约 0.85 倍 → 应 ≈1.25 | 略变宽 |

高度只矮了 **2.4%**，宽度只宽了 **0.2%**。这就是同一张站立图换了个细节，没有任何蹲伏压缩。游戏里 `dying` 的 0.85 秒它是"站着抖一下"，不是"腿软瘫坐"。

## 三、返工方案（推荐：只要 2 张原图）

关键认识：**4 帧跑步循环理论上只需 2 张原图。**

标准循环：F1 右腿支撑 → F2 腾空 → F3 = 镜像(F1) → F4 = 镜像(F2)。
后两帧由程序镜像生成，对称性 100% 保证，风格一致性 100% 保证。

这是旧素材的既有做法（F3≈镜像F1，IoU 0.950），有成熟脚本。

所以让豆包**只出 2 张**：
- **图A 支撑相**：一条腿竖直支撑承重，另一条腿向后抬起。
- **图B 腾空相**：两蹄都离地，前后交错。

要求：
1. 两张必须用**图生图**，以图A为底图改腿部生成图B，其余部位锁死。
2. 头部、羊毛、耳朵、尾巴、身体轮廓、深浅描边**一个字都不要变**。
3. 别改画幅、别改角色在画面里的位置和大小。
4. 交付时两图角色必须**同高、同头宽、脚底同高**。
