双击 `assets/preview/frames_player.html`

- 开「叠加残影」看四帧轮廓差异
- 开「脚底基准线」看有没有上下抖动

`assets/preview/run_8fps.gif`、`run_10fps.gif`、`run_12fps.gif` 是不用打开浏览器也能看的快速预览。

## 切帧坐标

竖排布局，从上到下取 `h` 高的块：

| 帧 | x | y（640 版，gap=24） | y（512/256/128 版，gap=0） |
|---|---|---|---|
| 1 | 0 | 0 | 0 |
| 2 | 0 | 664 | 尺寸 × 1 |
| 3 | 0 | 1328 | 尺寸 × 2 |
| 4 | 0 | 1992 | 尺寸 × 3 |

640 版帧间有 24px 透明间隔，**取帧时不要包含间隔**。
`sizes/` 下面是紧凑布局（间隔 0），直接 `y = (帧号-1) × 尺寸` 即可。

每档都配了 `sheet.json`，字段：`frameWidth / frameHeight / gap / anchor / poses / mirrorPairs / frames[]`。

## 锚点（重要）

锚点 = **脚底中心**。四帧的脚底全部落在同一条线上，把锚点钉在地面上，跑步时脚就不会上下漂、也不会左右抖。

| 尺寸 | anchor.x | anchor.y（脚底） |
|---|---|---|
| 640 | 320（母版元数据实测值，取半宽整；派生档为 319.5） | **603** |
| 512 | 255.5 | **483** |
| 256 | 127.5 | **241** |
| 128 | 63.5 | **120** |

`anchor.x = 尺寸/2 - 0.5`（F2~F4 的对称中心；F1 因手部细节差 0.5px，可忽略）。
`anchor.y` 各档都是**实测值**，不要用公式反推 —— 缩放取整会差 1px（例如 128 档公式算 121、实测 120）。

绘制时用这个点对齐地面，不要用图片中心。

## 帧序

**用 1 → 2 → 3 → 4 循环。**

像素镜像矩阵实测（IoU，越接近 1 越像）：

| 关系 | 值 |
|---|---|
| F1 vs 镜像(F3) | **0.950** |
| F1 vs F3（同向） | 0.682 |
| F2 vs 镜像(F4) | **0.839**（重绘前为 1.000 精确镜像） |
| F2 vs F4（同向） | 0.992（差异集中在右腿） |
| F4 vs 镜像(F1) / 镜像(F3) | 0.744 / 0.773（均不构成镜像） |

即 **F3 ≈ F1 的左右镜像；F4 是独立原创姿态，不再等于任何帧的镜像**（本轮重绘：右腿摆动抬升 44→28、外移 3px@256、宽度 71→63）。

一个周期是：**右腿支撑+左腿摆 → 左腿支撑+右腿摆 → 右腿支撑+左腿摆 → 左腿支撑+右腿摆**，支撑腿 **1:1 交替**。
（重绘前 F4 也是左支撑，形成 右→左→右→右 的 3:1 不均。）

相邻帧差异（1-IoU）：0.217 / 0.271 / 0.268 / 0.219 —— 四步接近，无重复帧、无缺帧。

帧率建议 **8~12 fps**。跑酷游戏常见 10~12 fps；嫌动作碎就用 8，嫌慢就 12。

## 身体起伏

头顶高度四帧依次 22 / 13 / 22 / 13（256 版），峰谷差 **9px = 身高 4.1%**，属于"轻微起伏"。
四肢负责动作，躯干只做小幅上下，不会一跳一跳。

> **F4 换代史（三次）**：
> ① 最早是双腿并立的对称蹲姿（自身镜像 IoU 0.982），让头顶峰谷差从 9px 变成 33px，循环像"瘸了一下"，且双臂同时后收；该帧保留为 `frames/sheep_run_4_squat_alt.png`（现用于受击姿势）。
> ② 随后换成 F2 的精确镜像，四帧配对整齐，但四条腿的支撑腿分布变成 右→左→右→右（3:1 不均），腿部节奏偏斜。
> ③ **本轮（当前）重绘为独立姿态**：保留 F2 版型与羊毛/腿根过渡，右腿整块（含抗锯齿边）下移 16px、外移 8px（640 档），腿根用上方羊毛像素列向延续填充。结果支撑腿恢复 1:1 交替、整帧仍是单连通块（无缺口/无碎片），脚底 603 与头顶 55/34/55/34 序列均未变。
> 重绘脚本：`.bj-agents/scripts/build_f4_v3.py`（生成）+ `.bj-agents/scripts/f4_commit.py`（落盘各档）。

## 已知的取舍

- **只有 4 帧**，跑步循环本身够用。如果要更细，一般会在腾空相再插 1~2 帧，变成 6 帧循环。
- **没有跳跃 / 落地 / 撞击帧**。如果游戏里需要这些状态，得另外做。
- 640 版单帧约 230KB，**不要直接塞进网页**，用 `sizes/256/`。
- F1 vs 镜像(F3) 是 0.950 而非 1.000，差在手指/羊毛边缘的 AI 生成细节；肉眼在 8~12fps 下看不出来。

## 出处

由文生图（2×2 四宫格 + 绿幕）生成后程序化处理：连通域分帧 → 按头宽归一化 → 底部基线对齐 → 竖排输出。
F4 早期由 F2 水平镜像生成；本轮改为「整块刚性重定位」重绘：从 F2 抠出右腿（含抗锯齿边）整体平移 8px 外 / 16px 下（640 档），腿根用上方羊毛像素列向延续填充，其余部位沿用 F2 版型。全程无旋转（旋转法会破坏蹄子纹理与小腿衔接）。
处理脚本在 `.bj-agents/scripts/`（`v2_analyze.py` / `v2_region_eval.py` / `v2_final.py` / `v2_make_player2.py` / `v2_sizes.py` / `build_f4_v3.py` / `f4_commit.py` / `audit_gait_final.py`）。
